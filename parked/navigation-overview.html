Navigation guide: De.KCD – Data Management Platform on the Cloud

How the pages fit together, and where to go for what

Published

November 18, 2026

This page is a map of the documentation. It does not repeat the content. It shows what is where, how the pages relate to each other, and in which order to read them depending on what you want to do.

It covers the ten content pages of the site menu. About and Privacy Policy are not covered.

TipThe one-paragraph version

The documentation helps you to choose the simplest setup that meets your current needs (a hosted service first, then local install, virtual machine, Docker Compose, Kubernetes) and to understand it well enough to find your way in each tool’s own documentation. Linux, containers, storage, backups, security, data protection, assemblies of several tools, semantic graphs and LLMs are covered in separate pages that point to each other.

Site map

Every box is a page of the site. Solid arrows are direct links between pages (the label says where they come from or what they carry). Dashed arrows are links to outside resources or thematic relations.

The complexity ladder

The core idea of the guide is to choose the simplest setup that meets your current needs, and to check first whether a hosted service already exists. When a ready-made image is available, Docker and then Docker Compose are the easiest ways to set a platform up, and Kubernetes is the step up when you need scale and availability. Installing by hand, in a virtual machine or on bare metal, is the fallback when no usable image exists or the application cannot be containerised: it is more work to install, update and maintain. The boxes carry the section of the step-by-step guide where each option is explained.

NoteWhat applies at every rung

Linux basics, scalability, databases, security, the Backups and Security page, automation, and the choice of tools are not tied to one rung. Treat them as a layer under the whole ladder.

Structure of the step-by-step guide

The home page is one long document. Its 19 sections fall into seven blocks. The guide says that each section assumes you know the previous ones, but you can skip what you already know.

Block What you get Learning difficulty stated in the guide
A · Orientation Scope, the five levels of setup, six common rules (keep difficulty under control, level of service, plan for problems not features, document changes, use version control) none
B · Foundations Commands, folders, users and groups, cgroups, firewall/SSH/VPN, remote display, web servers; vocabulary for bare metal, emulation and virtualisation easy to very hard, “intermediate” for a cloud installation
C · Containers Image, container, volume, Compose; a typical compose file with .env, health checks and YAML anchors; namespaces, bind mounts; multi-stage Dockerfiles Docker easy, Compose easy/medium, Dockerfile medium
D · Orchestration Pods, nodes, replicas, declarative manifests; when Kubernetes is overkill medium/hard
E · Other solutions Proxmox, OpenStack (Nova, Neutron, Cinder, Swift, Ceph, Magnum…), Nomad, Swarm, ECS, GKE, Cloud Run, six Apache projects not stated
F · Cross-cutting Vertical vs. horizontal scaling, relational vs. other databases, security checklist not stated
G · Operations Assemblies, Puppet/Ansible/Terraform, CI/CD and GitOps, choosing tools not stated

The decision tree, condensed

The page Technical platform decision tree contains the full tree. This is a shortened version to see the logic at a glance. The full tree adds a branch for institution-managed virtual servers (check backups, snapshots and load balancing there).

Note

The tree deliberately leaves out OpenStack and Proxmox (OpenStack is very complex; Proxmox only makes sense if your IT does not offer enough servers and someone has the time to run it). It also comes after a data management plan (see RDMKit).

The journey of the data across the pages

Six pages deal with the data itself, not with the infrastructure. They follow a natural order, from where the data lives to how it is described, queried and assisted by an LLM.

Outside the site

The documentation points to a few external resources repeatedly:

  • RDMKit (https://rdmkit.elixir-europe.org/): the wider context of research data management. The guide recommends starting there and using these pages for the technical depth.
  • FAIR-DMP-Registry (https://dekcd.github.io/FAIR-DMP-Registry/): the list of data management platforms the guide has in mind.
  • Hosted services named in the guide: De.NBI Cloud, European Open Science Cloud, EGI Federation, GWDG Academic Cloud and others.
